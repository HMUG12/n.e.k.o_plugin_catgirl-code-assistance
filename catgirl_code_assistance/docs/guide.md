# 猫娘代码协助 · 使用指南

> 一句话：把你本地的项目目录授权给她，然后用聊天的方式读代码、问代码、改代码。
> **所有内容都在本机处理，插件本身不发起任何网络请求。**

---

## 1. 三步起步

**第一步 · 授权可读文件夹**
打开插件设置面板 → 「可读文件夹」→ 每行填一个**绝对路径**，例如：

```
D:\projects\my-app
E:\repos\catgirl-core
```

保存后点「重建索引」。索引只记录**文件路径与元信息**（不含内容）。

**第二步 · 在聊天里开聊**

| 你想做的事 | 直接这样说 |
|---|---|
| 看项目有什么 | “这个项目有哪些文件？” |
| 找某个文件 | “帮我找名字里带 `config` 的 python 文件” |
| 找某段代码 | “`handle_login` 在哪被调用过？” |
| 读代码 | “把 `src/auth/login.py` 打开看看” |
| 看结构 | “这个文件整体结构是什么样的？” |
| 问大意 | “讲讲这个函数干嘛的，我看不懂” |
| 要建议 | “审查一下这个文件，哪些地方可以改进？” |
| 提改动 | “把这里的裸 `except` 改掉，先看 diff” |
| 真改 | “就按这个改，应用吧” |
| 改错了 | “撤回刚才那次修改” |
| 记点东西 | “记一下：这个项目的环境变量在 `deploy/env.sh`” |

**第三步 · 需要改代码时先开写权限（默认关闭）**
设置面板 → 「写权限（默认关闭）」→ 打开总开关，再勾选「允许修改已有文件」/「允许新建文件」。
即使开了权限，流程也永远是：**先看 diff 预览 → 你确认 → 才落盘 → 随时可撤销**。

## 2. 能力清单

| 能力 | 入口 | 说明 |
|---|---|---|
| 查看工作区状态 | `get_workspace_status` | 我当前能读哪些目录、索引了多少文件、权限如何 |
| 列目录 | `list_directory` | 返回每个条目的**完整绝对路径** |
| 找文件 | `search_files` | 支持通配符 `*.py`、`*util*` |
| 搜内容 | `grep_code` | 全项目正则，返回文件 + 行号 + 已脱敏的代码行 |
| 读文件 | `read_code_file` | 支持 `start_line` / `end_line` 读片段 |
| 结构大纲 | `code_outline` | 类 / 函数 / 签名 / 行号（Python 走 AST） |
| 解释上下文包 | `explain_code` | 内容 + 大纲 + 局部审查，一次给全 |
| 代码审查 | `review_code` | 本地静态检查，给出改进建议 |
| 符号定位 | `find_symbol` | 找函数 / 类的定义位置 |
| 改动预览 | `propose_edit` | **只读**，产出 unified diff，不需要写权限 |
| 应用改动 | `apply_edit` | 需写权限；自动备份，可回滚 |
| 新建文件 | `create_file` | 需写权限；父目录必须已存在 |
| 撤销 | `undo_edit` | 从本地备份还原上一次改动 |
| 改动历史 | `list_edit_history` | 列出最近改动记录 |
| 项目笔记 | `remember_note` / `list_notes` / `forget_note` | 跨会话记住项目约定 |

> **故意不提供删除文件的入口**：删代码的代价远大于收益，请用你的 IDE 或 Git 来做这件事。

## 3. 隐私：什么会离开你的电脑

**只有经过本地脱敏的文本片段返回给大模型**，原文永远留在你的磁盘上。

脱敏覆盖：私钥块、AWS Access Key、GitHub Token、OpenAI Key、Slack Token、Google API Key、
JWT、Bearer Token、数据库连接串（含账密）、硬编码 `password/secret/api_key=` 赋值、
邮箱、手机号、身份证号、银行卡号。命中项会被替换成 `[REDACTED:XXX]`。

你还可以在设置面板追加自己的正则。

**三重边界：**
1. **目录白名单** —— 不在「可读文件夹」里的路径一律拒绝，包括伪装成路径的符号链接；
2. **本地脱敏** —— 返回前过滤；
3. **零网络** —— 插件代码里没有任何 HTTP 客户端调用，纯标准库实现。

> 说明：正则脱敏能挡住常见写法，但挡不住刻意把密钥拆开再拼接的做法。
> 真正的安全边界是目录白名单和不联网。

## 4. 我不做的事情（省得误会）

- 不会执行你的代码、不会跑 shell 命令；
- 不会上传任何一个文件，也不读取 `.git` 历史（`.git` 在默认屏蔽目录里）；
- 不会删除文件；
- 不会联网查资料。

## 5. 出问题先看这里

| 现象 | 原因与处理 |
|---|---|
| 说“路径不在允许的可读文件夹内” | 该路径没被授权。去设置面板加进「可读文件夹」，或先用 `search_files` 取正确路径 |
| 说“不是绝对路径” | 别手写相对路径，用 `search_files` / `list_directory` 返回的完整路径 |
| 说“扩展名不在允许清单内” | 在设置面板的「允许的文件扩展名」里补上 |
| 说“没有匹配到 old_text” | 文件内容已变。**先 `read_code_file` 取最新内容**再拼 `old_text`（含缩进） |
| 搜索结果为空 | 先点「重建索引」；索引没建好时会退化为实时遍历，结果可能不全 |
| 说“写操作总开关未打开” | 设置面板打开写权限 |
| 改动后想反悔 | “撤销刚才那次修改”；备份存在插件私有目录 `backups/` |

---

## 6. 推荐的正确姿势

1. 先 `code_outline` 看结构，再 `read_code_file` 读具体片段 —— 比整篇读省很多 token；
2. 想改动时**必须**先 `propose_edit` 出 diff 给用户看，得到确认后才 `apply_edit`；
3. 一次改动聚焦一处，改完就能干净地撤销；
4. 长会话里用 `remember_note` 记住约定，下次直接 `list_notes` 回忆。
